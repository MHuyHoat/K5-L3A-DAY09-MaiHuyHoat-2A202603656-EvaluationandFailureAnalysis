### 3.2 Luồng xử lý của orchestrator

```
claim → Orchestrator đọc get_claim_view (không SELECT *)
  ├─ claim không tồn tại            → failed   (unknown_claim)
  ├─ thiếu order_id                 → needs_info (không đoán mã đơn từ ticket)
  └─ make_handoff(facts={}, tool đọc) → run_readonly_investigators
       lookup_order, lookup_policy, lookup_refund_history, compute_compensation
  ├─ đơn không thấy / sai principal → escalated
  ├─ quote = 0                      → denied   (không gọi issue_refund)
  └─ quote > 0 → issue_refund(conn, claim_id, quote đầy đủ, crash_at=crash_at)
       ├─ ok        → resolved
       ├─ conflict  → failed
       └─ host chặn → denied (host ghi audit policy_denied)
```

### 3.3 Quyết định kỹ thuật

1. **Ranh giới code / model.** Investigator chỉ nhận tool đọc (`INVESTIGATOR_TOOLS`). Có hai lớp chặn tool ghi: `make_handoff` ném `HandoffError`, và `dispatch(..., worker=True)` ném `ToolRejected`. Tiền do `compute_compensation` tính trên order row. MockLLM chỉ được gọi một lần với `purpose="draft"` để soạn chữ, không quyết số tiền, không gọi tool ghi.
2. **Handoff với `facts={}`.** Investigator tự đọc dữ kiện từ DB bằng tool đọc. Ticket, `parent_secret`, `raw_headers` và claim row không đi qua handoff. Nếu có field lạ lọt vào, `sanitize()` vẫn cắt theo allowlist. Nhóm không dùng tóm tắt bằng LLM để thay cho redaction, vì LLM có thể chép lại hoặc diễn đạt lại secret.
3. **Truyền quote đầy đủ vào `issue_refund`.** Host tự trừ phần đơn đã được hoàn bởi claim khác. Nếu shape tự trừ trước thì bị trừ hai lần, và T14 (C-014: quote 150.000, đã hoàn 30.000, ledger đúng là 120.000) sẽ fail.
4. **Crash.** `crash_at` được truyền thẳng vào `issue_refund`. Khi gặp `InjectedCrash`, shape ghi event `crash` vào trace rồi `raise` lại chứ không nuốt lỗi, vì T12 kiểm crash có thật sự xảy ra hay không. Idempotency key `refund:{claim_id}` của host đảm bảo lúc resume không ghi thêm dòng thứ hai.
5. **Trace cố ý không ghi**: nguyên văn ticket, claim row, order row thô (phone, address, item_name, internal_note), `principal_id`, parent context. Trace chỉ ghi:
   - `handoff`: bản đã sanitize
   - `investigator`: `order_visible`, `order_reason`, `already_refunded_vnd`
   - `quote`: `amount_vnd`, `reason`, `clause_ids`
   - `decision`: `status`, `proposal_amount`, `reason`

   Mọi nhánh return đều đi qua `finish()`, nên luôn có trace đúng `run_id`.
